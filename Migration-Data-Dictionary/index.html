    Complete field-level mapping from mainframe VSAM/COBOL structures to PostgreSQL database schema.

    Overview

    This document provides complete field-level mappings between mainframe COBOL copybook structures and PostgreSQL database tables. Each mapping includes: - Source COBOL field definition - Target PostgreSQL column definition - Data type conversion rules - Validation rules - Sample data transformations

    Mapping Conventions

    Naming Conventions: - COBOL: UPPERCASE-WITH-HYPHENS - PostgreSQL: lowercase_with_underscores

    Data Type Mappings: - PIC 9(n) → BIGINT or INTEGER - PIC X(n) → VARCHAR(n) - PIC S9(n)V99 COMP-3 → DECIMAL(n+2,2) - Date strings → DATE or TIMESTAMP

    COMP-3 (Packed Decimal) Conversion

    COBOL COMP-3 Format: - Storage: 2 digits per byte (except last byte: 1 digit + sign) - Example: PIC S9(10)V99 COMP-3 = 6 bytes - Value: 12345678.90 stored as: 12 34 56 78 90 0C (hex)

    Conversion Algorithm:

    public BigDecimal convertComp3ToDecimal(byte[] comp3Bytes, int scale) {
    StringBuilder digits = new StringBuilder();

    for (int i = 0; i < comp3Bytes.length; i++) {
        byte b = comp3Bytes[i];
        int highNibble = (b >> 4) & 0x0F;
        int lowNibble = b & 0x0F;

        if (i == comp3Bytes.length - 1) {
            // Last byte: digit + sign
            digits.append(highNibble);
            boolean negative = (lowNibble == 0x0D);
        } else {
            digits.append(highNibble);
            digits.append(lowNibble);
        }
    }

    BigDecimal value = new BigDecimal(digits.toString());
    return value.movePointLeft(scale);
}

    Card Number Validation (Luhn Algorithm)

    public boolean validateCardNumber(String cardNumber) {
    int sum = 0;
    boolean alternate = false;

    for (int i = cardNumber.length() - 1; i >= 0; i--) {
        int digit = Character.getNumericValue(cardNumber.charAt(i));

        if (alternate) {
            digit *= 2;
            if (digit > 9) {
                digit = (digit % 10) + 1;
            }
        }

        sum += digit;
        alternate = !alternate;
    }

    return (sum % 10 == 0);
}

    Mainframe Timestamp Conversion

    Mainframe Format: YYYY-MM-DD-HH.MM.SS.NNNNNN (26 characters) Example: 2025-11-21-10.30.45.123456

    PostgreSQL Format: YYYY-MM-DD HH:MM:SS.NNNNNN Example: 2025-11-21 10:30:45.123456

    Conversion:

    public Timestamp convertMainframeTimestamp(String mfTimestamp) {
    // Input: 2025-11-21-10.30.45.123456
    // Output: 2025-11-21 10:30:45.123456

    String formatted = mfTimestamp
        .substring(0, 10) + " " +  // Date part
        mfTimestamp.substring(11, 13) + ":" +  // Hour
        mfTimestamp.substring(14, 16) + ":" +  // Minute
        mfTimestamp.substring(17, 19) + "." +  // Second
        mfTimestamp.substring(20);  // Microseconds

    return Timestamp.valueOf(formatted);
}

    Password Migration Strategy

    Important: Mainframe passwords cannot be directly migrated due to different hashing algorithms.

    Options:

    1. Force Password Reset (Recommended)
    2. Set temporary password for all users
    3. Force password change on first login

    4. Send password reset email

    5. Generate Random Passwords

    6. Generate secure random password for each user
    7. Hash with BCrypt
    8. Send to users via secure channel

    BCrypt Hashing:

    import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;

public String hashPassword(String plainPassword) {
    BCryptPasswordEncoder encoder = new BCryptPasswordEncoder(12);
    return encoder.encode(plainPassword);
}

    Special Conversions

    Packed Decimal (COMP-3):

    // Example: Convert PIC S9(10)V99 COMP-3 (6 bytes) to BigDecimal
public BigDecimal convertPackedDecimal(byte[] bytes) {
    long value = 0;
    boolean negative = false;

    for (int i = 0; i < bytes.length; i++) {
        byte b = bytes[i];
        int high = (b >> 4) & 0x0F;
        int low = b & 0x0F;

        if (i == bytes.length - 1) {
            value = value * 10 + high;
            negative = (low == 0x0D);
        } else {
            value = value * 100 + high * 10 + low;
        }
    }

    BigDecimal result = BigDecimal.valueOf(value).movePointLeft(2);
    return negative ? result.negate() : result;
}

    Binary (COMP):

    // Example: Convert PIC 9(04) COMP (2 bytes) to Integer
public int convertBinary(byte[] bytes) {
    return ByteBuffer.wrap(bytes).getShort();
}

    Business Rules

    Customer Data Rules

    1. Customer ID: Must be unique, 9 digits
    2. SSN: Must be unique (if provided), 9 digits
    3. Name: First and last name required, middle name optional
    4. FICO Score: Range 300-850, or 0 for not scored
    5. Date of Birth: Must be in the past, age >= 18 for primary cardholder

    Account Data Rules

    1. Account ID: Must be unique, 11 digits
    2. Credit Limit: Must be >= 0
    3. Cash Credit Limit: Must be <= Credit Limit
    4. Current Balance: Must be >= -Credit Limit (no over-limit)
    5. Expiration Date: Must be > Open Date
    6. Active Status: Y or N only

    Card Data Rules

    1. Card Number: Must be unique, 16 digits, pass Luhn check
    2. CVV: 3 digits
    3. Expiration Date: Must be future date
    4. Active Status: Y (Active), N (Inactive), B (Blocked), E (Expired)
    5. Card-Account Relationship: Each card must belong to exactly one account

    Transaction Data Rules

    1. Transaction ID: Must be unique
    2. Amount: Can be positive (charge) or negative (credit/payment)
    3. Transaction Type: Must exist in transaction_types table
    4. Category Code: Must exist in transaction_categories table
    5. Card Number: Must exist in cards table
    6. Timestamp: Original timestamp <= Processed timestamp

    User Security Rules

    1. User ID: Must be unique, 8 characters max
    2. User Type: ADMIN or USER only
    3. Password: Must be BCrypt hashed, minimum 8 characters
    4. Email: Must be unique, valid email format
    5. Status: ACTIVE, INACTIVE, or LOCKED

    Validation Queries

    Post-Migration Validation

    -- 1. Record count validation
SELECT 'customers' as table_name, COUNT(*) as count FROM customers
UNION ALL
SELECT 'accounts', COUNT(*) FROM accounts
UNION ALL
SELECT 'cards', COUNT(*) FROM cards
UNION ALL
SELECT 'transactions', COUNT(*) FROM transactions
UNION ALL
SELECT 'users', COUNT(*) FROM users;

-- 2. Referential integrity checks
-- Accounts without customers
SELECT COUNT(*) as orphaned_accounts
FROM accounts a
LEFT JOIN customers c ON a.customer_id = c.customer_id
WHERE c.customer_id IS NULL;

-- Cards without accounts
SELECT COUNT(*) as orphaned_cards
FROM cards c
LEFT JOIN accounts a ON c.account_id = a.account_id
WHERE a.account_id IS NULL;

-- Transactions without cards
SELECT COUNT(*) as orphaned_transactions
FROM transactions t
LEFT JOIN cards c ON t.card_number = c.card_number
WHERE c.card_number IS NULL;

-- 3. Data quality checks
-- Null values in required fields
SELECT 'customers' as table_name, 
       COUNT(*) as null_first_names
FROM customers 
WHERE first_name IS NULL;

SELECT 'customers' as table_name,
       COUNT(*) as null_last_names
FROM customers
WHERE last_name IS NULL;

-- Invalid credit limits
SELECT COUNT(*) as invalid_credit_limits
FROM accounts
WHERE credit_limit < 0 OR cash_credit_limit > credit_limit;

-- Expired cards still active
SELECT COUNT(*) as expired_active_cards
FROM cards
WHERE expiration_date < CURRENT_DATE AND active_status = 'Y';

SELECT COUNT(*) as overlimit_accounts
FROM accounts
WHERE current_balance > credit_limit;
